TECHNICAL DOCUMENTATION: "OSTEOGEN" MODULAR PIPELINE [v2]
Architecture for the Generative Reconstruction of Animals from Fossils/Skeletons

1. SYSTEM OVERVIEW AND INFRASTRUCTURE
OsteoGen starts from a fossil/skeleton image (even of an animal never photographed alive, e.g. a dinosaur) and produces: (a) a percentage biological-compatibility report against the animals in a geometric database, and (b) a generative render of the reconstructed animal. The pipeline is organized into four macro-phases:
1) Anatomical keypoint detection via Deep Learning (ResNet18).
2) Scale-invariant biological retrieval, with a percentage score (not just the single best match).
3) Generation of a human-readable report (HTML/JSON) of the retrieval result.
4) Generative render (local diffusion, ControlNet + IP-Adapter) conditioned on the target's skeleton and on the donors' textures weighted by compatibility.

Note v1->v2: the final compositing stage used to rely on rigid triangle
warping (convexHull + estimateAffine2D), which produced pasted-together
texture fragments rather than a coherent animal (see
outputs/trex_chimera_render.jpg for an example of the problem). That
warping code was not discarded: it was repurposed as the control-map/raw-
guide generator for the generative stage (see render/control_map.py),
which is now the actual final output.

The training infrastructure is designed for an NVIDIA GPU with enough VRAM
for SD1.5+ControlNet+IP-Adapter (roughly an RTX 5080, 16 GB VRAM) and a
still-small training set (65 animals): this part does not need saturated
CUDA cores or tens of GB of VRAM and stays lightweight; the generative
render is the heaviest stage.

2. PHASE I: DATA PREPARATION AND GROUND TRUTH
The goal of this phase is to standardize the inputs and define the spatial annotations used for training.

A. preprocess_target.py
- Goal: prevent geometric distortion (bone squashing) on external inference targets (e.g. raw T-Rex skeleton photographs).
- How it works: the module computes a scale factor based on the original image's longer side, resizing it while preserving the aspect ratio. It then applies letterboxing to place the silhouette inside a square, black 512x512 tensor, matching the visual style of the 65 training samples.

B. keypoints.py
- Goal: generate the ground truth by defining the (x, y) coordinates of the joints.
- How it works: using Matplotlib, the tool captures 14 sequential points per skeleton. It implements an anatomical-tolerance mechanism: clicking near the origin (x<10, y<10) marks that joint as "Null" (needed to handle the absence of a tail in some phenotypes). The coordinates are serialized to JSON.

C. heatmap.py
- Goal: convert discrete coordinates into differentiable training targets for backpropagation.
- How it works: implements the `SkeletonKeypointDataset` class. For each annotated point, the module computes a 2D heatmap by applying a Gaussian distribution (sigma=5.0). It returns batches made of the ImageNet-normalized image tensor (3x512x512) and the heatmap target tensor (14x512x512).

D. check_heatmap.py
- Goal: preliminary diagnostic validation of the generated tensors.
- How it works: collapses the 14 Gaussian maps along the channel axis (dim=0) and overlays them on the original input to visually verify perfect bone-to-target spatial alignment before any training compute is spent.

3. PHASE II: TRAINING THE ENCODER-DECODER
This is the predictive core, responsible for mapping skeletal features onto activation maps.

E. resnet.py
- Goal: build a neural architecture able to extract high-level features and reconstruct the native resolution.
- How it works: the `ResNet18KeypointDetector` class uses a Transfer Learning approach, taking a ResNet18 encoder (ImageNet weights) to reduce the input to a 16x16x512 volume. The decoder is a sequence of `ConvTranspose2d` layers with `BatchNorm2d`. The final layer has no activation (no Sigmoid/ReLU): the raw logits are fed directly into the Weighted MSE loss described below, rather than being squashed into [0, 1] first.

F. train.py
- Goal: optimize gradients while preventing overfitting on a small dataset.
- How it works: the training loop uses a "Weighted MSE Loss": instead of a plain squared error, the loss applies an asymmetric penalty, multiplied by 50, on pixels with Gaussian activation above 0.05, forcing the network away from trivially converging on the empty background. Stability is provided by the AdamW optimizer (weight decay 1e-4), gradient clipping, and a `ReduceLROnPlateau` scheduler that halves the learning rate after 10 epochs without improvement. An Early Stopping mechanism (patience=25) prevents weight degradation, while visual telemetry and checkpoints are saved dynamically every time the best loss improves.

4. PHASE III: INFERENCE AND BIOLOGICAL COMPOSITION
The final segment processes the network's output to recreate the chimera using computer-vision algorithms.

G. inference.py
- Goal: extract anatomical coordinates on out-of-distribution (OOD) samples.
- How it works: disables gradient computation (`torch.no_grad()`) and processes the target image. For each of the 14 predicted channels, it finds the probability peak via `np.argmax`, applying a confidence threshold to discard hallucinated points. Coordinates on the 512x512 map are then rescaled to the input's absolute dimensions.

H. geometry.py [v2]
- Goal: the single source of truth for the 14-keypoint schema, the 5-part anatomical segmentation, and the geometric normalization (translation + scale) shared by build_DB.py, compatibility.py, and render/.
- How it works: the preferred scale reference is the torso (neck-base -> tail-base); when unavailable (body plans with no annotated tail: frog, snake, turtle, chimpanzee, human, bat), an "equivalent torso" is estimated from the skull, corrected by the average skull/torso ratio calibrated on the dataset (without this correction, distances between the two populations explode - verified empirically on turtle.png: from dist~2.3 down to dist~0.4, in line with the rest of the dataset). Segment lengths are computed as the sum of the chain's links (not the direct first-to-last distance): for the torso, the direct distance coincides by construction with the scale anchor (~1.0 for every animal, a useless comparison), while the shoulder/back/hip chain reflects how arched the back actually is.

I. build_DB.py [v2]
- Goal: build the geometric database used by the retrieval stage.
- How it works: reads the hand-annotated coordinates in Labels_X (ground truth) instead of re-running inference on the training images (the network exists to read keypoints on images it has NEVER seen, not on already hand-annotated ones - using it here would only add noise). For each animal it stores both the raw and the normalized coordinates (geometry.normalize_keypoints) and the segment lengths. The resulting JSON has the structure {"_meta": {"skull_calibration_factor": ...}, "animals": {...}}.

J. compatibility.py [v2, replaces match_dinosauro.py]
- Goal: a percentage compatibility report, not just a single "closest match wins".
- How it works: two levels. (1) species_compatibility compares the target's normalized keypoints against every animal in the DB (RMS over the shared points) and converts the distances into percentages with a softmax (temperature calibrated empirically: matching an animal in the DB against itself keeps the self-match at 50-100% instead of a near-uniform ranking). (2) segment_compatibility does the same but on the proportions of each of the 5 anatomical segments, used to choose the render's texture donors. compatibility_report combines both into a single structure.

K. report.py [v2, new]
- Goal: make the report readable by a human, not just consumable by code.
- How it works: generate_json_report saves the raw structure; generate_html_report produces a self-contained HTML page (no external dependencies, images embedded as base64) with a bar chart of compatible species and thumbnails of the best donors per segment.

L. render/control_map.py [v2, formerly warp_dinosauro.py]
- Goal: no longer produces the final image. The rigid triangle warping (outputs/trex_chimera_render.jpg in v1) produced pasted-together texture fragments rather than a coherent animal: the problem was not the keypoints (well aligned, see outputs/debug_heatmap_trex.jpg) but expecting an affine transform over 2-3 points to be enough to compose an entire body.
- How it works today: draw_control_map traces the target's skeleton as white polylines on black, independent of the original image's style - this is the input fed to a ControlNet in the generative stage. generate_raw_guide keeps the original warping logic (convexHull/tubular mask/estimateAffinePartial2D) but only as an optional init-image for a low-strength img2img pass, not as the final output.

M. render/generate.py [v2, new]
- Goal: the actual generative render.
- How it works: a local diffusers pipeline (Stable Diffusion 1.5 + ControlNet conditioned on the skeleton's control map + IP-Adapter conditioned on the best donors' photos, weighted by compatibility by repeating images in proportion to their weight rather than a plain average). The text prompt is built automatically from the report ("50% eagle, 30% chicken, ..."). Requires a CUDA GPU; weights are downloaded from Hugging Face on first use.

N. pipeline.py [v2, new]
- Goal: the single end-to-end CLI.
- How it works: chains preprocess_target -> inference -> compatibility -> report -> render (the last step is optional via --no-render, to produce only the report without needing a GPU/diffusers weights).
